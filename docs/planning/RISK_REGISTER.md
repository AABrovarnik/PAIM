# Реестр рисков — Review 01
Дата: 2026-11-24. Качественные оценки, не статистика. Владельцы рисков — предлагаемые роли, фактически контроль у владельца проекта.
| ID | Риск | Вероятность/ущерб | Контроль | Роль |
|---|---|---|---|---|
|R01|Сложность ведения задач|В/В|Ввод одного названия, пилот|UX|
|R02|Срыв срока|В/В|Заморозка P0, перенос P1|CPO|
|R03|Выдуманные поручения|В/В|Черновик, цитата источника, неизвестные поля null|AI|
|R04|Дубликаты|В/С|Уникальные ID источника, кандидат на объединение|CTO|
|R05|Перегрузка|В/В|Резерв, предупреждения|COO|
|R06|Потери при синхронизации|С/К|Версии, идемпотентность, конфликт без перезаписи|CTO|
|R07|Несанкционированное действие|С/К|Проверка прав и подтверждение на backend|CISO|
|R08|Prompt injection|С/К|Недоверенный контент, allowlist инструментов, структурированные данные|CISO|
|R09|Усталость от уведомлений|В/С|Дайджест, тихие часы, дедупликация|UX|
|R10|Отказ AI|С/В|Ручной CRUD без AI|CTO|
|R11|Расходы API|С/С|Лимиты, учет, остановка AI при бюджете|CFO|
|R12|Планирование вместо работы|В/В|Три результата, короткий обзор|COO|
|R13|Утечка данных|С/К|Секреты вне Git, синтетические тесты, фильтр логов|CISO|
В — высокий, С — средний, К — критический. Критические риски блокируют эксплуатацию с реальными данными до проверки мер. Остаточный риск и фактическое прохождение тестов фиксируются при приемке.
