## Статусы и ограничения
Task: inbox, ready, in_progress, waiting, deferred, done, cancelled; overdue вычисляется, deleted_at отдельно. inbox→ready после разбора; ready/in_progress/waiting/deferred взаимно по решению владельца; done/cancelled можно явно открыть вновь; завершение с незакрытыми детьми/предшественниками требует предупреждения и явного override. Делегирование — отдельное состояние drafted/sent/accepted/in_progress/submitted/verified/declined/cancelled; sent в MVP фиксируется вручную (отправка поручений не автоматизирована). 
Удаление проекта с активными задачами запрещено до переноса/архива; удаление родителя с детьми требует явного выбора перенести или удалить поддерево; корзина 30 дней (предлагаемый default), восстановление проверяет связи. 
Срок date-only трактуется как конец локального дня, timestamp — точный момент. Перенос задачи меняет только planned block, изменение due отдельной операцией.

## Нормативное уточнение v1.1 (GM-01–08, GM-10–12, CH-01–08)
FR01/07: контекст day/project/date создает ready, day дополнительно добавляет task в список выбранного локального дня (не обязательно в топ-3); inbox или отсутствие контекста создает inbox, в т.ч. /add без контекста. Явная дата = выбранный пользователем deadline или плановая дата, не неявный дедлайн. Быстрый ввод использует чипы сегодня/завтра, время, проект; название единственное обязательное поле. Неоднозначность остается текстом до выбора. Ручные inbox tasks переводятся PATCH в ready; внешние inbox_items(new) принимаются отдельной атомарной операцией с ручным редактированием, даже без AI proposal; один результат на элемент, связь source, повтор не создает дубль. Пакетный выбор — preview списка и отдельные идемпотентные операции по элементам, частичный результат видим. Не создавать обязательство автоматически.
FR08: независимый быстрый приоритет high/medium/low/unset, стандартная матрица I/U, экспертный индекс I/U/R/B. Неизвестное null не равно нулю; I/U null -> needs_assessment, важные без срока выделяются отдельно; Q2 только при известной U<7. Явный выбор квадранта устанавливает I/U (7 или 3), отмечается manual, без заполнения R/B. Последствия выполнения/невыполнения — отдельные редактируемые поля задачи; AI предлагает изменения, не перезаписывает ручные значения. 
FR06: отдельная сущность commitments сохраняется: task XOR event, контрагент, обещанный результат, срок, контрольная дата, status open/fulfilled/cancelled. Показывать в карточке и фильтре Ожидаю (секции «Поручения» / «Мои обязательства»). Приемка обязательства явная; закрытие задачи не закрывает его автоматически. Быстрый пресет «Жду ответа от X до даты» создает контакт/задачу/поручение drafted либо sent только если владелец явно отметил уже переданное; не отправляет сообщения. submitted→verified или in_progress (возврат с причиной); declined означает отказ исполнителя, не отказ в приемке результата. Копирование текста напоминания локально.
FR04/11/12: дневной план сохраняется вручную, до 3 ранжированных результатов плюс остальные задачи дня, подтверждение и повторное подтверждение после изменения. Выбор не создает календарный блок или дедлайн. Перенос/завершение/удаление сохраняют историю подтвержденной ревизии; активный план помечает изменения и требует пересмотра. Емкость учитывает только пересечения с рабочими окнами; неизвестную трудоемкость показывать отдельно; блок 30 минут предлагается только при ручном размещении без оценки, редактируется до сохранения, estimate не подменяется. Слоты — детерминированный список доступных интервалов вручную, автоматический подбор/перепланирование P1. Вне рабочего окна показывать отдельно. Умные списки и горизонты определены в A02/UI_UX. Вечерний и недельный обзор SQL-фактов без LLM; до трех AI-рекомендаций по умолчанию, раскрытие остальных вручную.
FR13/14/18: смена timezone применяется к новым планам/датам, существующие due_tz/series tzid/подтвержденные планы не сдвигать. Все клиенты Web/TG используют общие версии, операции и права. Принятые/отклоненные элементы не переоткрывать автоматически после смены промпта. Удаление памяти/источника инвалидирует кэш, убирает производные чувствительные фрагменты; исторические backups истекают по политике, restore повторяет purge перед использованием. Состояние внешнего календаря stale при ошибке или возрасте синхронизации >2 интервалов; нельзя обещать актуальную доступность; внешний preview обновляется перед записью.
