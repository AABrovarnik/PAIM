# PAIM — Personal AI Manager

Дата: 2026-11-24. Статус: концепция, до экспертизы.

## Назначение
Личный AI-ассистент для задач, мероприятий, напоминаний, проектов, целей и делегирования. Интерфейс — компромисс между Microsoft To Do и MS Project. Целевой срок разработки с Codex: 4–6 недель после согласования объёма.

## Требования владельца
- Одиночные и регулярные задачи: создание, изменение, перенос, удаление; подзадачи и делегирование.
- Источники: почта, совещания, мероприятия, соцсети, личные цели и интересы.
- Приоритизация важно/срочно, последствия выполнения и невыполнения.
- Единое хранилище документов, этапов и исследований: https://github.com/AABrovarnik/PAIM.

## Предлагаемая организация репозитория
- docs/concept/ — версии концепции.
- docs/research/ — исследования и сравнительные обзоры.
- docs/board/ — регламент совета, экспертные заключения, Red Team, решения.
- docs/requirements/ — ТЗ, сценарии, критерии приёмки.
- docs/architecture/ — архитектура, схема БД, API, безопасность, ADR.
- docs/planning/ — roadmap, этапы, статус, риски.
- docs/testing/ — тест-планы и результаты.
- prompts/ — промпты агентов.
- apps/ — код приложений после утверждения ТЗ.

## Правила
Markdown, даты ISO, статусы draft/review/approved/superseded. Сохранять историю решений и источники исследований. GitHub Issues — предлагаемый инструмент управления работами; существенные изменения через PR, merge после подтверждения владельца. Репозиторий публичный: не хранить ключи, реальные письма, календарные записи, персональные данные или дампы БД. Использовать синтетические тестовые данные. Папки создаются по мере появления документов.

## Этапы
1. Концепция V1 — предварительно обсуждена.
2. Экспертный совет и Red Team — предложены, не проведены.
3. Концепция V2 и утверждение границ MVP.
4. Детальное ТЗ и архитектурный аудит.
5. Реализация Codex, тестирование и развёртывание.
6. Независимый аудит готового приложения.

Технологический стек и структура каталогов предварительные, подлежат рассмотрению советом.
