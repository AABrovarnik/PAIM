# Personal Information Map (PIM) — концепция
Статус: DRAFT | 2026-11-25. Карта знает не только где искать, но что считать актуальной истиной, как получить доступ и что делать при сбое.
## Реестр типов источников (кандидаты, не фактические подключения)
| Область | Авторитетный источник | Чтение | Запись P0 | Особенность |
|---|---|---|---|---|
| Почта | Gmail | live search, ограниченные выдержки | нет | письмо не равно принятому поручению |
| События | Google Calendar | live events, free/busy, выбранные календари | нет | время/зона/прозрачность |
| Задачи/повторы | один готовый органайзер, выбор предстоит | live tasks/projects | нет в read-only пилоте | deep link, provider ID |
| Код/Issues/PR/документация проектов | GitHub и явно выбранные рабочие ресурсы | API/разрешенные файлы | нет | ветка/commit, PR не равен merge |
| Библиотека | выбранные Drive/локальные папки | выборочный индекс/поиск | нет | оригинал не копировать без нужды |
| Общение | Telegram, диалоги по явно доступному каналу/экспорту | собственные сообщения ассистента, пересланное | только свои уведомления по разрешению | нет обещания доступа ко всей истории ChatGPT/Telegram |
| Цели/интересы/принципы | приватная память PAIM или указанный пользователем реестр | structured lookup | явное редактирование/подтверждение | источник, срок актуальности |
| Решения/ретроспектива | приватный журнал PAIM + evidence links | structured + RAG | подтвержденные записи | отличать факт от самооценки/гипотезы |
| Новости/исследования | утвержденные публичные источники | web/RSS по теме | нет | дата публикации и события, дедуп |
## Минимальная модель
Source: source_id, type, display_name, provider, account_ref (opaque), scope, authority_for, access_mode, locator, auth_ref (secret vault pointer), enabled, refresh_policy, last_success, health, retention_policy, allowed_collections, privacy_class.
ObjectRef: source_id, external_id, object_type, canonical_url, version/etag/hash, observed_at, effective_at, title sanitized, project_ref, freshness, tombstone.
Relation: from_ref, relation_type (supports/mentions/part_of/derived_from/conflicts_with/supersedes), to_ref, evidence_ref, confidence, confirmed_by_owner, updated_at. Простые связи SQL достаточно для P0.
Не хранить секреты в карте, не публиковать реальные имена аккаунтов/календари/пути. Ссылки локальных файлов только в приватной среде. Если ресурс нельзя открыть через API, использовать ручной экспорт/ссылку с отметкой last_import; не выдавать за live. 
## SoT и конфликты
Назначить ровно один SoT для каждой изменяемой сущности/поля, возможны разные источники задач для разных областей только при явной маршрутизации. Отображение может объединять источники, но не сливать без явного решения. Email/meeting extraction -> candidate obligation с цитатой, не задача автоматически. Конфликт сроков показывается с обоими источниками; authoritative due не меняется по совету модели. Разделить deadline, time block, meeting time, estimate, check_at. Не считать Git-коммиты или количество писем доказательством прогресса.
## Инвентаризация перед пилотом
Для каждого ресурса: владелец, назначение, разрешенные папки/labels/репозитории, наличие API/OAuth, лимиты/тарифы/экспорт, глубина истории, метод обновления/удаления, чувствительность, альтернативный доступ. Проверка на реальной среде только после отдельного разрешения. Выбор органайзера зависит от API read/write, recurrence/subtasks/delegation, deep links, export/portability, UX, цены и доступности в регионе; прежний UX-бенчмарк не доказывает доступность API.
