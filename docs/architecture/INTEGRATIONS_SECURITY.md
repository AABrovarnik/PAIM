# Integrations & security
## Gmail
OAuth separate consent, gmail.readonly scope (verify actual grant/verification requirements in spike). Poll configurable 30 min, initially selected labels/allowlist, denylist takes precedence; default exclude spam/trash. Initial lookback 7 days, max 100 messages/run; pagination and checkpoint after durable insert, overlap safe. Fetch text/plain or sanitized HTML to text, no attachments P0, no remote resources. Store minimum excerpt and ID, not raw body. No send/labels/delete. On expired/revoked token show reconnect, no infinite retries.
## Google Calendar
Read chosen calendars, event IDs, ETags, timestamps, all-day, timezone, cancelled/transparency, recurrence instances. Sync token per collection and consistent query params; 410 invalid token => staged full resync; don't purge local projection before successful reconciliation. External event ownership remains Google. MVP external write only to explicitly selected writable calendar, no automatic invites/attendees, preview + owner confirmation; reject unsupported recurring external series edits (Google UI alternative), local recurring tasks fully supported. Stable client-generated event ID for create when supported; ETag conditional update/delete; verify uncertain outcome by lookup. Free/busy derive union from imported selected calendars; stale data marked. No writes during initial spike except isolated test calendar with permission.
## Telegram
Long polling; store update_id dedupe, one owner/private chat, binding code TTL 10 min; /start, /today, /inbox, /add, /waiting, /help, /cancel; plain text/forward -> inbox source draft; /add explicit manual task (inbox without context, ready with explicit project/date/day); inline approve/reject bound to actor/proposal/hash and expiry. No token in logs or URL output. Rate limit, quiet hours, delivery status. Bot can send reminders to bound owner only.
## Meetings/social
Paste text or forward messages to bot; extract action items with evidence. No recording, scraping, impersonation, direct social APIs or file attachments P0. No assumption that meeting attendance implies commitment.
## Threat model and controls
External input is untrusted; sanitize markup, reject tool instructions from content, restrict model to typed proposals, no arbitrary shell/browser/DB/network access. All writes authorized server-side. Least privilege OAuth, encrypted tokens with separate key, secret rotation and revocation, TLS, CSRF, session expiry default 12h idle/7d absolute, login throttling, password hash Argon2id. Validate ownership at every route including nested IDs/export/jobs. Allowlist external destinations and provider endpoints; no URL fetch from arbitrary source. No cross-origin wildcard. Secure headers, dependency/secret scans, no prod secrets in CI. Audit actor, target, action, time, outcome, redacted diff, request ID. 
## Confirmation policy
L0/L1 read/suggest; L2 explicit confirmation; L3 only preauthorized reversible internal drafts/reviews/notifications to owner, no external calendar write/send. Approval bound to exact operation and actor; 15 min default; replay returns existing status without another effect; changed target requires new preview. Never let AI approve itself. Bulk changes preview each item and use same rule.
## Operations/privacy
Encrypted daily backups, restore test, retention per schema. Export and deletion of memory/source excerpts; source references may remain if owner chooses. Disconnect stops new sync and revokes credentials where supported. Existing local data retained until user requests removal. Public repository only synthetic examples; redact logs. Production access and OAuth availability not yet verified.

## v1.1: external failure, freshness and privacy
Follow A07 state machine, no blind retry after dispatch. Calendar create stable provider resource ID, conditional ETag updates/deletes; verify exact intended resource/version/effect; if outcome ambiguous or worker may still send, read-only reconciliation then manual resolution. Do not assume Telegram send has provider idempotency; internal in-app delivery deduped, uncertain Telegram delivery visible, no automatic resend. Telegram callbacks use opaque server-side proposal handle (not full payload), validate owner/private chat/actor/hash/expiry/version; callback acknowledgement does not imply action completed. Both Web and TG use same command service. 
Read sync stale when failed/revoked or >2 configured intervals; show last success. Fresh provider checks before external writes; degraded read-only releases require explicit owner decision and UI banner. Gmail reanalysis uses stable source/candidate identity; never auto-reopen decided item. Filter sources at intake, do not forward full mail or unrelated content to LLM. Prompt schema validation, no direct tool capability. Budget reserves concurrent calls and unknown-price fails closed.
Retention default source excerpt 90d configurable pending owner decision; purge source and derived sensitive excerpts, AI cache, review snapshots, prevent automatic reimport, retain minimal noncontent dedupe marker where needed. Restore encrypted backup in isolated environment; replay encrypted purge manifest before enabling service, verify deletion and disconnect tokens until explicitly reauthorized. Backup expiry 14d proposed; no promises of immediate physical deletion of historical backups/provider originals. Provider-side data deletion separate. Audit matrix ADR-006. No production writes for WP00 without separate permission, see SPIKE_GATE.
