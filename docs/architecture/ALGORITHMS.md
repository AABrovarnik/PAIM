# Algorithms and rules
## A01 Priority (FR08)
I importance to goals, U urgency, R risk of omission, B incremental benefit, each integer 0..10 or null. P=3I+2.5U+2.5R+2B; custom weights sum 100, nonnegative; P=sum(w*x/10). If any positive-weight input null, P=null (not zero, no normalization by known weights). Threshold >=80 high, >=50 medium, else low. Independent quick_priority high/medium/low/unset, set in one click without changing I/U/R/B. Matrix threshold 7 for known I/U; unknown either -> needs_assessment, I>=7 and no due additionally appears in strategic list, not automatically Q2. Explicit quadrant presets set I/U to 7 or 3 with manual origin, leave R/B untouched. Example 8,5,9,7 =>73.0/Q2. AI explains evidence and assumptions; manual overrides survive reassessment until explicitly cleared, including separate task if_done_text/if_not_done_text. Store weight snapshot. Urgency default for explicit due: overdue or <=24h 10, <=3d 8, <=7d 6, <=30d 4, later 2; no deadline null unless user specifies urgency. Hard deadlines and blocked flags separate. Ranking for manual daily suggestions: actionable tasks only (ready/in_progress, not blocked unless override); hard deadline at risk first, quick_priority high/medium/low/unset, complete P descending (null last within same quick priority), due ascending (null last), stable ID. User can select any eligible task, not required to accept suggestions. 
## A02 Day plan (FR04/11/12)
Day D is local calendar date in recorded IANA timezone. Convert intervals to UTC, merge overlapping work windows, clip to day. W=sum work minutes. Busy=union of noncancelled nontransparent events and locked active blocks, intersect W. Reserve=ceil(W*reserve_pct/100). Capacity=max(0,W-busy-reserve). Demand=sum durations of each unlocked active block intersect W (sum, not union, to expose double-booking), plus remaining estimate=max(0,estimate-actual) for selected ready/in_progress tasks with no active block on D and no blocking dependency; exclude completed/cancelled/deleted and blocked without override from forecast, flag them separately. If a selected task has a block on D, count explicit time only and show any unallocated estimated remainder separately (remaining estimate minus all active block duration on D, min 0). Locked blocks counted in busy only. Always display unknown_count (selected actionable tasks with null estimate) and outside-work-window block minutes separately; no inference that unknown work fits. remaining=max(0,capacity-demand); overload=max(0,demand-capacity,busy+reserve+ demand-W). Example 480-120-120=240; 300 planned -> overload 60; 20:00 block outside W does not reduce capacity. Detect overlaps across all actual busy/locked/unlocked intervals including outside W, separate from capacity, transparent events do not block. Manual free-slots = W minus union of busy/locked/unlocked blocks; show reserve and stale warning, do not autoassign. P1 automated first-fit suggestion respects remaining capacity, reserve, earliest/deadline and dependencies, preview only.
Daily plan GET/PUT synchronous; unique owner/date/tz, draft/confirmed, item order and <=3 unique outcome ranks. Choose/replace outcomes, add other tasks, allow skipping steps. Confirmation snapshots capacity and items in immutable revision with recorded tz. User edits membership/rank after confirmation create draft and reason; explicit reconfirm creates new revision. Completion changes live progress, not past snapshot and does not force reconfirm. Moving a block marks current plan capacity changed; moving a planned task to another day is explicit remove/add membership, never alters due; delete removes live item, flags review and retains redacted history. No external write. Evening/weekly review facts available synchronously; up to 3 default recommendations.
Smart lists: eligible active = ready/in_progress/waiting/deferred, not deleted/template; inbox separate. Today/My day = union of selected day membership, blocks intersecting D, due local date D, overdue active tasks (dedupe by task ID; show completed planned tasks separately); waiting/deferred flagged, not actionable automatically. Upcoming = active tasks due or blocked in calendar (time blocks) in D+1..D+30 or future plan membership in that interval, grouped by earliest qualifying date, dedupe; undated = active tasks without due, any future/current active block or day-plan membership today/future; waiting = active waiting tasks or active delegations or open commitments, grouped. Date-only deadline at end of recorded due_tz day; timestamp deadline local display converted to viewer timezone. Overdue uses actual instant, not displayed label. Horizons show D, [D,D+7), [D,D+30), [D,D+90), [D,D+1 calendar year) (Feb29->Feb28 next year), distinct tasks/events/goals/milestones with relevant dates, backlog/overdue and estimated hours deduped within horizon; undated goals separate. No implicit date mutation. Timezone changes apply to new date-only due/series/plans, preserve old keys, tz and absolute instants.
## A03 Recurrence (FR03)
Use tested RFC5545 subset DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, BYDAY (weekly), BYMONTHDAY (monthly), COUNT XOR UNTIL; local DTSTART+TZID; validate DTSTART matches rule. Preview cap 1000 and rolling 90d materialization; compute finite counts from DTSTART, not materialized window. Generate valid nominal local keys in chronological order before exceptions. Invalid calendar date or nonexistent DST local time skipped and does NOT consume COUNT; show warning. Ambiguous DST uses earlier instant, counted once. Explicit skip/cancelled exception consumes one valid original occurrence, override retains original key and consumes one even if moved; completed instances consume one. For future split at original key K, let B=count(valid base keys strictly before K), remaining=N-B for finite COUNT N, including K; previous rule terminates before K (COUNT=B, deactivate if B=0); new rule starts at user-confirmed new DTSTART, COUNT=remaining unless explicit new COUNT. Example N=6, B=3 => 3 remaining even if one earlier key cancelled or overridden, invalid dates not included in B. Reject split on nonexistent key, exhausted rule or mismatched preview/version. UNTIL preserved as cutoff unless explicitly changed; reject new DTSTART beyond it. No COUNT+UNTIL. Future exceptions identified by old ordinal relative to split, preview mapping to new ordinal/key; require explicit keep mapped or drop, reject out-of-range/duplicate override until resolved. Never silently drop. If completed instance exists in affected future segment, reject 409 and offer later split or single edit to preserve immutable history without duplicate occurrence. Single edit modifies only uncompleted instance via skip/override; completed immutable except explicit task reopen outside series edit. All applies new rule to current/future uncompleted segment (first original valid key >= now in series timezone), preserves all historical keys and completed history; same split/exception safety, update template for future. Historical past never retroactively recreated. Delete series scope explicit: disable/truncate affected rule and soft-delete uncompleted selected instances, retain completed history. Transaction locks owner/series; preview hash binds original version, rule, exception mapping and new rule. Upsert unique rule/key; retire affected old future instances and rebuild reminders atomically; pending stale jobs cancelled. Test with COUNT+Feb31, DST gap, skip/moved/completed and split beyond materialization window.
## A04 Source handling (FR07/14/17)
Normalize and dedupe provider ID before LLM; extract structured candidates with evidence spans, dates nullable; resolve relative dates only with source timestamp/timezone and flag assumptions. Validate schema, reject invalid values; if no actionable content classify idea/reference. Deduplicate exact source; similar title+counterparty+deadline is a merge candidate, never silent merge. On approval transaction creates task and links evidence, idempotency proposal ID. No obligation created by raw import. 
## A05 Dependencies (FR02/09)
DFS/topological sort on candidate directed edge, reject cycles; transaction/advisory lock prevents concurrent cycle. Parent tree max depth 10. Progress completed leaves/active leaves, cancelled excluded; empty project 0. Blocked if predecessor not done; override explicit with reason. 
## A06 Reminders (FR05)
Resolve absolute or anchor due/start/check + offset; missing anchor -> disabled with reason. Job dedupe reminder/occurrence/scheduled timestamp/channel. Quiet hours shift normal notifications to end; critical only if owner explicitly enabled bypass. Snooze creates new timestamp, cancels pending prior job. Retry transient failures, uncertain provider response mark uncertain; do not claim guaranteed exactly-once Telegram. Persistent in-app inbox deduped.
## A07 Confirmation and worker state (FR05/15/17/18)
Canonical payload hash binds actor, operation, resource, target_version, ETag, destination and expiration (15 min default). Owner approval transaction locks proposal, validates pending/unexpired/exact hash, creates unique approval and job, immutable operation_id. Repeated approve returns current state, never creates new dispatch. Reject/revoke/expire before dispatch cancels. Worker must recheck actor/account permissions, hash, version, ETag, expiry and revocation in atomic dispatch transition; after dispatch cancellation not guaranteed, use explicit compensating operation. No arbitrary tools/shell.
Job queued→leased→dispatching→succeeded (proposal approved→executing→applied). Claim via SKIP LOCKED and monotonic lease_token++; every update/heartbeat uses token + expected state; expired pre-dispatch lease can be requeued with new token, expired dispatching job becomes reconcile_pending and proposal uncertain_reconcile_pending; new worker only reads provider, no blind resend. Durable dispatch_started_at and immutable operation ID committed BEFORE network; old worker must recheck token before call, stale responses cannot commit. Fencing cannot fence provider itself. Timeouts/unknown outcomes after dispatch marker also reconcile_pending; confirmed known-no-effect failures may retry (max 5, jitter/backoff, recheck authorization/expiry), known permanent failure→failed/dead_letter; mismatch before dispatch→conflict/cancelled job. Reconcile read-only stable provider ID/ETag and exact intended effect; if confirmed applied -> succeeded/applied, if definitively no effect and original attempt quiesced -> failed (new approval required for new write), if inconclusive after bounded 5 attempts -> uncertain_manual. Never treat absent immediate lookup as proof of no effect or retry while old request may execute. Telegram uncertain delivery has no universal lookup; manual resolution/visible notice, no auto-resend. Provider-side idempotency/conditional requests where supported, verify in WP00. Reconcile continues after approval expiration only read-only. Expose operation_id, dispatch time, attempt counts, next/last reconcile, result ref/error; terminal states retained. Audit state transition and authorization failures. 
## A08 Reviews/memory (FR12/13/14/17/18)
SQL facts overdue, due horizon, Q2/unknown, waiting check, capacity, unestimated, goals without progress, plan versus completed outcomes. Manual review synchronously without AI; jobs optional summary max 3 advice by default (expand extras), fact IDs and assumptions. Unique kind/period_start/tzid; revisions audited, historical dates unchanged on timezone edit. Preference explicit edit; AI suggestions require approval; delete invalidates cache. Reprocessing source with new prompt never reopens accepted/dismissed candidate; only explicit new review of distinct candidate with evidence. Budget gate reserves worst-case estimated cost transactionally before request (including in-flight), reconciles actual usage; unknown price blocks paid request; no bypass via fallback. Purge propagates to dependent excerpts/cache/reviews and restore replay per schema.
