# Algorithms and rules
## A01 Priority (FR08)
I importance to goals, U urgency, R risk of omission, B incremental benefit, each integer 0..10 or null. P=3I+2.5U+2.5R+2B; custom weights sum 100, nonnegative; P=sum(w*x/10). If any positive-weight score null, P=null, show missing. Threshold >=80 high, >=50 medium, else low. Matrix threshold 7 independently for I/U. Example 8,5,9,7 =>73.0/Q2. AI explains evidence and assumptions; manual overrides survive reassessment until cleared. Store weight snapshot. Urgency default if explicit due: overdue or <=24h 10, <=3d 8, <=7d 6, <=30d 4, later 2; no deadline null unless user provides urgency. Hard deadline and blocked flags separate; do not imply all hard deadlines urgent. 
## A02 Day plan (FR11)
Convert working intervals to timezone-aware UTC; union busy events (excluding transparent/cancelled) and locked blocks, intersect with work windows; reserve=work_minutes*reserve_pct/100. capacity=max(0,work-busy-reserve); remaining=max(0,capacity-unlocked planned minutes). Union for availability, additionally report overlapping blocks and their total requested minutes. Example 480-120-120=240; 300 planned -> overload 60. Check deadline feasibility against earliest start, duration and dependencies; unknown duration shown unestimated. Choose up to three actionable outcomes: hard deadlines at risk, priority desc, due asc, stable ID; user overrides; blocked tasks appear separate. No automatic shifts P0. P1 first-fit free slots, respect bounds, reserve, predecessor and locked blocks, preview only.
## A03 Recurrence (FR03)
Use tested RFC5545 library subset DAILY/WEEKLY/MONTHLY/YEARLY, INTERVAL, BYDAY (weekly), BYMONTHDAY (monthly), COUNT or UNTIL exclusive choice; local DTSTART+TZID. Validate rule; cap preview 1000 and rolling 90d materialization; regenerate via worker. Missing calendar date skip; nonexistent DST local time skip with warning; ambiguous time choose earlier offset and display; retain stable original local key. Upsert unique rule/key; single edit exception; future splits series at selected occurrence, old rule ends before it, new rule retains remaining COUNT if finite unless explicit change. all edits regenerate uncompleted future only, retain completed history and exceptions or preview incompatible ones. Delete series disables rule and soft-deletes selected future occurrences; explicit scope required. Reminder jobs rebuilt idempotently; cancel stale jobs.
## A04 Source handling (FR07/14/17)
Normalize and dedupe provider ID before LLM; extract structured candidates with evidence spans, dates nullable; resolve relative dates only with source timestamp/timezone and flag assumptions. Validate schema, reject invalid values; if no actionable content classify idea/reference. Deduplicate exact source; similar title+counterparty+deadline is a merge candidate, never silent merge. On approval transaction creates task and links evidence, idempotency proposal ID. No obligation created by raw import. 
## A05 Dependencies (FR02/09)
DFS/topological sort on candidate directed edge, reject cycles; transaction/advisory lock prevents concurrent cycle. Parent tree max depth 10. Progress completed leaves/active leaves, cancelled excluded; empty project 0. Blocked if predecessor not done; override explicit with reason. 
## A06 Reminders (FR05)
Resolve absolute or anchor due/start/check + offset; missing anchor -> disabled with reason. Job dedupe reminder/occurrence/scheduled timestamp/channel. Quiet hours shift normal notifications to end; critical only if owner explicitly enabled bypass. Snooze creates new timestamp, cancels pending prior job. Retry transient failures, uncertain provider response mark uncertain; do not claim guaranteed exactly-once Telegram. Persistent in-app inbox deduped.
## A07 Confirmation (FR15/17)
Create canonical payload hash incl actor, operation, resource, target_version, external ETag, recipient/calendar, expiration (default 15 min). Show diff. Approve only pending unexpired exact hash by owner; transaction locks proposal, approval unique, job unique. Worker rechecks authorization/version/etag before external call; mismatch -> conflict, fresh preview. Deny/revoke before dispatch cancels; after dispatch use explicit compensating operation. Timeout after external call => reconcile by stable external ID before retry, or uncertain/manual. No arbitrary shell/tool invocation.
## A08 Reviews/memory
SQL aggregates for facts: overdue, due horizon, Q2, waiting check, capacity, unestimated, goals without recent progress. AI optional summary with fact IDs. Daily/weekly jobs use owner local time; unique kind/period; manual refresh creates revision or replaces with audit. Preference explicit editing; AI suggestions only after approval; deletion invalidates prompt cache.
